## How to read this

- **One row per bug.**
  - **ID:** `R<review>-<finding>` for a Codex review finding (report at `codex/reviews/<review>-*/report.md`); `K-<area>-<n>` for a known issue from a step record, `LANDINGS.md` or Jesus's play reports (`play-checklist.md`).
  - **Sev:** high / med / low, as verified. "(P)" marks a plausible finding, not yet proven against vanilla.
- **Repro:** steps in a survival generated world unless noted. Families need `foundation.Blocks.Families 1` until it ships on.
- **Where:** the likely `file:function` (paths under `Source/Unnamed/` unless noted). **Value:** the value source to fix against (VALUES = `value-holder\MINECRAFT-26.3-VALUES.md`, FINDINGS = `SURVIVAL-FINDINGS-26.3.md`, RUN2 = `SURVIVAL-RUN2-FINDINGS-26.3.md`).
- **Status:**
  - **open:** deferred to QC.
  - **in-flight <step>:** already routed to a step before the freeze; check it after that step lands.
  - **post-QC:** Jesus chose to fix it after QC.
- **Triage (QC coordinator PM 6, 2026-10-16 ~08:15 UTC; only the coordinator edits this file now):**
  - **Pri:** P1 crash, test integrity, high; P2 item loss, stuck input, broken combat/containers, common mediums; P3 other mediums and cheap lows nearby; P4 obscure lows. Separate from Sev.
  - **Effort:** S (hours, local) / M (several files or a runtime check) / L (investigation or rendering). **Risk:** regression risk L/M/H.
  - **Evidence:** static (a Codex review/audit reading; not runtime proof), runtime (seen in a run), play (Jesus), record (a step record), needs-probe (vanilla unknown; request R25 in `value-holder\REQUESTS-SURVIVAL.md`).
  - **Batch:** `qc/QC-FIX-PLAN.md` section 9. `-` = unbatched (P4 or waiting on a probe).
  - **New statuses:** `deferred (<why>)` = a not-built or deferred feature (`QC-FEATURE-STATUS.md`), never a bug; `needs-recheck` / `needs-repro` = the fix chat checks first.
