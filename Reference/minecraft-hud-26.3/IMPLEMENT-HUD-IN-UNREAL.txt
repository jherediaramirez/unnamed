ARCHITECTURE
Prefer a local-player-owned native Slate HUD, consistent with the current foundation. UMG is acceptable for suitable authored components, but keep one coherent view model and shallow hierarchy. Do not use gameplay Chromium/WebBrowser or turn the HTML research viewer into the runtime HUD.

Create a gameplay-to-HUD adapter publishing a coherent snapshot: mode/capabilities; health/max/absorption; armor; food/saturation; air/maxAir/eyesUnderwater; effects; XP level/progress/recent-display tick; selected slot and item presentations; handedness/offhand; attack charge/target eligibility; vehicle health/jump/cooldown; approved waypoints; hide-HUD/debug/camera/screen-focus state. Fields for absent systems must carry explicit validity/support, not silently default into fictional production values.

Keep snapshot state distinct from presentation history (last/displayed health, blink clocks, item-name timer, air-pop guard, icon animation). Compute geometry and sprite choice in pure testable functions. The paint function only consumes that output. Gameplay owns resource changes, authority, persistence and item transactions; widgets never apply damage, regenerate health, consume stacks or award XP. When networking exists, gameplay data comes from the appropriate server-authoritative owners and client feedback is confirmatory. No widget scans all world actors for locator data.

ASSETS
Import additively through an Editor-only script into a dedicated HUD content folder. Keep the original files untouched. Create a registry mapping source path to cooked texture/brush, native dimensions, animation frames/timing, GUI slice rules and semantic role. The manifest contains per-file hashes.

Small pixel icons: nearest sampling, no mipmaps, preserved RGBA, suitable UI compression, sRGB for ordinary color artwork, clamp addressing, no resizing/padding that changes UVs. Check the installed engine's actual property APIs. Large blurred overlays, animated fire/portal and item glint use separate appropriate materials. Honor every .png.mcmeta; the locator background is a 12x5 nine-slice drawn 182x5, and its arrows are 7x10 sheets with 7x5 frames lasting 10 then 4 ticks. Dots are distance variants, not animation frames.

Font PNGs are glyph atlases with provider JSON, not whole text images. Use the supplied font metrics/Unicode dependencies through an appropriate adapter, or explicitly report an agreed font substitution. Stack counts, names, XP numbers, chat, scoreboard and subtitles remain text. Item models, skins, durability rectangles and cooldown rectangles are runtime dependencies, not missing HUD PNGs.

BEHAVIOR CONTRACT
Health: normal maximum 20 points; one full heart=2, half=1; ceil display health. Draw container, absorption, blink-history and current layers in source order. Poison > Wither > fully frozen > normal. Hardcore selects artwork. Absorption extends containers; max health and absorption are different. Keep delayed displayed health (~1 second), damage/heal blink windows (20/10 ticks under cooldown), three-tick blink bands, <=4-point jitter and regeneration's raised-heart step. Derive extra rows/armor displacement exactly from the report; do not hardcode ten hearts.

Food: 20 points, six normal/Hunger variants, saturation-dependent jitter; no invented stamina/saturation bar. Sprint food eligibility is >6 food points, not low-health based. Existing movement eligibility remains owned by the movement/gameplay system.

Air: render while eyes underwater OR air<max. Default max=300 ticks, ordinary depletion=1/tick, refill=4/tick. At 20Hz that is 15 seconds to zero, first ordinary drowning hit around 16 seconds, then 2 damage each second; 0-to-full refill takes 3.75 seconds. These are gameplay reference rules, not a request to put damage in the widget. Respect oxygen modifiers, invulnerability, Water Breathing/Conduit, and Nautilus preventing depletion without independently refilling. Use full/bursting/empty formulas and surface refill behavior in the report. Gate bubble-pop audio once per transition if audio is implemented; never play it on every paint.

Context state: with waypoints, active jump/cooldown takes priority, then recent XP for 100 ticks when mode supports it, then locator. Without waypoints: jumpable mount, else XP-capable, else empty. Level>0 text is independent. XP uses floor(183*p) crop; mount/boss discrete fill uses zero at zero and floor(181*p)+1 for p>0. Crop fill UV/destination; never squeeze an entire progress texture.

Crosshair: replace the font '+' with the actual sprite. Honor first-person/spectator/3D-debug gates. Native inverse blending is a real visual requirement; prove the chosen compositing path on bright and dark scenes or document its remaining gap. Crosshair attack background/progress is 16x4; full marker is 16x16 with a living in-range ready target and source attack-delay conditions. Hotbar attack meter fills vertically on the opposite side from offhand. This is not mining progress.

Effects: 40 icon mappings, showIcon/ambient flags, source sorting, neutral effects in lower row, final-200-tick pulse; do not always show every available icon. Mount health replaces food and shifts air. Boss bars are event-driven by stable ID. Peripheral chat, player-list, subtitles, title/action messages, spectator and toasts are separate layers driven by their actual features. Camera overlays use correct blending, aspect, intensity and animation; do not import the whole animated sheet as a static giant icon.

Mode/F1/focus: Survival/Adventure stat block, Creative suppression, spectator selector and gated crosshair. Vehicle/locator capability is separately evaluated. Passive HUD is hit-test invisible. Preserve input ownership through menus, inventory/chat fixtures, capture, focus loss and pause. Keep existing F3 telemetry separate and avoid two crosshairs/two HUDs after integration. Respect source exceptions instead of hiding unrelated screens by toggling one global UI root.
