# Foundation architecture

Entry: existing main menu → Singleplayer → **Playground** → `/Game/Maps/L_Playground`. Escape opens a pause page inside the existing CEF menu; Options/Controls are the original screens and bridge. Resume and return wait for all three browser settings queues. Native `UMenuApplication` checks and drains native services before starting a selected level. Pause suspends this single-player pawn's simulation; diagnostics and UI continue ticking. It does not globally freeze Unreal's render loop.

## Ownership

- `UUnnamedInputSettings` and its `UEnhancedInputUserSettings` key profile remain the binding/hold-toggle authority and SaveGame owner. Schema 1 adds debug scale/sections. Registering existing stable row IDs retains customized mappings; new uncustomized defaults come from the native contexts. `UMenuInputBridge` validates, rejects conflicts, applies, clears intent, and saves. The project defaults are Left Shift sprint and C crouch. `CreateInputAssets.py` authors them for a new project; `SetupFoundation.py` restores only the known accidental Ctrl/Shift factory rows introduced by the first Foundation build, preserving other authored keys. Saved custom profiles are retained. No old save file is deleted or converted to HTML storage. Vanilla default keys remain research evidence, separate from the project's chosen layout.
- `UMenuPreferences` remains the single native JSON owner of sensitivity, inversion, auto-jump, sprint window, attack/use toggle, scroll sensitivity/discrete scroll, FOV and FOV effects. The pawn/router read these live. Other desired video/audio/language/pack preferences remain at their earlier implementation stage; the tooltip distinguishes the newly applied settings.
- `UMenuVideoSettings` retains fullscreen and the existing five live video settings. Its object survives pause/resume and F11 uses it. Offscreen verification deliberately has no native window-mode capability. Global engine debug exec bindings are cleared on the Foundation player controller so development F1/F5/Shift commands cannot intercept the game's controls; editor viewport shortcuts are unaffected.
- `UFoundationProfile`, configurable in `[/Script/Unnamed.FoundationProfile]` in DefaultGame.ini, centralizes reference movement constants in cm or cm/reference tick. Its C++ defaults are the verified baseline; a deliberate override belongs in that section. Block scale is a fixed project invariant: 100 cm. `FFoundationEligibility` is the mobility/food/item-slowdown boundary: `FFoundationVitals` supplies death (mobility) and food each step; item slowdown has no owner yet.

## Controller parts

`AFoundationController` (a plain `APlayerController`) owns four components and coordinates them; nothing inherits from the menu controller:

- `UMenuBrowserHost` - the shared offline menu, shown as the pause menu, plus the `foundationmenu` bridge (`UFoundationMenuBridge`).
- `UFoundationInputRouter` - Slate preprocessor, F3 chords, binding capture and stale-key blocking.
- `UFoundationHud` - unchanged F3 overlay, one native `Hud` presentation leaf, event log and debug drawing (display only).
- `UFoundationPanels` - Debug Options, the chat/command text fixture and the inventory: the creative inventory screen (`SHudCreativeScreen`) in the Playground, the routing fixture elsewhere.

The controller handles logical actions, held-action repeats, pause/resume and focus loss, and updates the parts once per frame in a fixed order: timing, main-hand check, motion and vitals log, wheel release, held actions, debug draw, HUD refresh.

## Input path

Windows Slate event → physical-key adapter → capture/text/menu/global routing → Enhanced Input mapping → requested intent or typed action → fixed simulation/fixture eligibility → resolved pose/velocity/action result → telemetry.

`IMC_OnFoot` priority 0 preserves separate directional mapping rows feeding cumulative `IA_Move`. `FoundationActions` priority 10 is a transient context drawn from the registered `IMC_FoundationActions` asset, excluding debug-only mappings. The latter remain registered for settings and displayed in Controls. Only the diagnostic chord router can activate them. This prevents plain D/C/B from consuming gameplay before the modifier is held. Mouse look accumulates X/Y deltas; native axis smoothing/FOV scaling/legacy scales are disabled. The sensitivity formula is applied once, without frame-time multiplication.

`UFoundationInputRouter` registers the one Slate preprocessor on the Foundation controller (the plain menu map has none). Capture wins, followed by focused blocking UI and global diagnostics; gameplay requires possession, no menu/panel/capture, and active contexts. F3 release toggles only after an observed unconsumed F3 press. F3+F6 also works when perspective has been rebound to F6. Keyboard events that enter text continue through normal Slate/CEF character and editing dispatch. Windows layout translation is read-only; it does not switch the user's OS layout.

Opening UI, losing activation, changing bindings, or changing possession flushes intent, cancels action fixtures, and blocks held keys until release. Repeated contexts are added/removed using Enhanced Input's supported APIs, with `bIgnoreAllPressedKeysUntilRelease`. No toggle/attack resumes merely because focus returns. This cancellation policy deliberately differs from vanilla's optional toggle restoration.

Same-context or same-debug-chord duplicates are rejected; the user must clear or change the other row. Bare gameplay and debug chord keys may overlap. Overlay/modifier may intentionally share F3. Escape and the console key are reserved. Backspace unbinds during capture. Wheel is an extension: a rebound wheel pulse lasts through one reference simulation step, then releases; unbound wheel scrolls the nine slots. Positive/negative fractional accumulation and direction changes are handled independently of UI scrolling. Fixed Ctrl for stack-drop does not follow rebound sprint. Capture's selecting input is never gameplay input.

## Simulation and collision

`AFoundationPawn` is a feet-origin pawn, a world-aligned query box, one camera and, in the third-person views, the player body ([below](#player-body-and-the-third-person-views)). Its actor and collision axes do not rotate with view yaw. `FFoundationSimulation` advances at 20 Hz: the pawn takes the due steps (`TakeDueSteps`) and runs each one followed by its `FFoundationVitals` step; `AFoundationPawn::Tick` handles look/render interpolation independently. Maximum five catch-up steps; discarded time is explicit telemetry. Camera eye height and collision height remain separate during crouch and blocked standing. Camera-only rear/front views use a collision-clipped offset and reveal the player box.

The collision provider is `AFoundationLab`'s immutable cuboid list, with matching native engine cube components. `AFoundationLab::BuildLayout` builds the 2 km ground (`AddGround`, top z = 0) and the movement course (`BuildMovementCourse`) around `CourseOrigin`; every solid goes through the virtual `AddSolid`. The Playground overrides `AddSolid` so each solid is also an authority static (targetable, occluding, blocking placement); only grid-aligned solids anchor placement. The reference-like solver clips world-axis boxes and tests step candidates/edge support. It intentionally does not claim arbitrary Unreal mesh, moving-platform or slope support. Rebased world offsets update feet and the lab's collision/target boxes. `FoundationCoordinates` alone owns east/south/up conversion, negative flooring and inverse position/angle conversion.

## Player body and the third-person views

The player body is Better Steve (`C:\dev\projects\better-steve`), imported by `Scripts/Editor/ImportBetterSteve.py` from `Art/Characters/BetterSteve` into `UUnnamedProjectSettings::PlayerBodyRoot` (`/Game/Characters/BetterSteve`): `SK_BetterSteve` (187.5 cm, 56 bones with UE Mannequin names, facing +Y) and its 43 actions as AnimSequences named after them (`BS_Idle`, `BS_Walk_F`, ...). The pawn adds the body at BeginPlay when the mesh and every clip exist (otherwise it logs `Player body: ... missing` and the views keep the hitbox outline). There is no Animation Blueprint; three pieces split the work ([record](../Records/2026-10-13-Player-Body.md)):

- **`FFoundationBodyTurn`** (`FoundationBody.h`, pure): the body's yaw, stepped with the simulation at 20 Hz and drawn between the last two steps. `foundation.Body.Yaw` picks the rule: 0 the view's yaw; 1 (default) vanilla's (0.3 of the way per step toward the travel direction, the opposite of travel more than 95 degrees off the view, the head at most 50 degrees off the body; these constants are unverified, recalled); 2 the travel direction, backward too (third-person orient-to-movement).
- **`FFoundationBodyAnimator`** (`FoundationBody.h`, pure): once per rendered frame, from the interpolated simulation (horizontal velocity, eye height, grounded, crouched, flying, jumps started), it picks the clips with their times and weights. Locomotion blends idle and the two neighbouring of 8 directions by speed, each clip at the game's own straight or diagonal speed (walk 431.72 / 440.53 cm/s, sprint 561.23 / 572.69, crouch 129.52 / 183.16), so keyboard input lands on one clip; each stance shares one phase (every loop starts on the left foot's touchdown), and the phase advances before the pose is built, so a planted foot stays put. The stances blend by the eye height; standing still, a crouch toggle plays `BS_StandToCrouch` or `BS_CrouchToStand`. Air: `BS_Jump_Start` from a jump, `BS_Jump_Loop` when it ends or after 0.15 s of any other fall (and while flying), `BS_Jump_Land` on touchdown (skipped when landing on the move). The head: the 9 `BS_Look_*` poses, bilinear over yaw and pitch -90..90 (control rotation minus the body's yaw; a view behind the body turns the head back toward the front).
- **`UFoundationBodyAnimInstance`**: a native anim instance whose proxy samples those clips (`UAnimSequence::GetAnimationPose`), blends them and adds the look poses as mesh-space additive rotations (they are made additive on `BS_Look_C` frame 0 at import).

The body component sits at the interpolated feet with absolute transforms (the actor stands at the latest step), ticks after the pawn, and shows in F5's back and front views only (`foundation.Body` 0 hides it); it also hides when the camera is pulled within 40 cm of the eyes. While it shows, the cyan hitbox outline is drawn only with the collision boxes.

`foundation.View.SpringArm` 1 (default 0) is a third-person preview: F5's back view becomes an over-the-shoulder spring arm (325 cm back, 55 cm right, 30 cm up from the eyes; the pivot trails the eyes at 12/s, at most 75 cm; the camera turns after the view at 15/s), pulled in by the world's own boxes with `FFoundationSimulation::Clip` like the vanilla views (a stock `USpringArmComponent` would trace UE physics and miss the blocks). Targeting, reach and the outline stay the eyes' and the view's; the crosshair is first-person only, so the preview shows none. A third-person game would need its own targeting: the eyes' aim line runs 55 cm left of and 30 cm below the screen centre's line, a large angle at block-reach distances.

`-Suite body` (`FoundationBodyProbe.cpp`, not part of all) poses the body in the back, front and spring-arm views (idle, walk, sprint, crouch, crouch walk, jump, look up and down, the yaw rules), with a shot and the expected clip each, and measures the planted feet's drift while walking and the spring arm's length in the open and against the ground.

## Actions and diagnostics

`FFoundationActionRequest` carries action, phase, resolved target and modifier facts. `FFoundationActionResult` carries acceptance/reason/hand. `FFoundationActions` is explicitly a test double with nine token counts and an offhand count: it cannot create items, damage entities, place terrain or mine. Eye-ray targeting uses separate 450 cm block and 300 cm entity reach, strict boundaries, and nearest-hit occlusion. The tiny numerical boundary guard is 0.0001 cm because Epic's line-box API returns a float interpolation fraction. Native collision geometry is rectangular; complex entity selection boxes are deferred.

F3 samples formatted telemetry at 10 Hz and retains at most 24 discrete events. Input contexts/priorities come from the live Enhanced Input subsystem; frame/CPU/GPU timings come from engine counters when nonzero. Unavailable counters are labelled. Target ray tests scan the small fixture list; there are no expensive terrain queries or per-frame event log writes. Debug scale, section mask and coordinate preference use the existing input SaveGame. Copy snapshot uses the native clipboard. The passive overlay is hit-test-invisible. Chat and the inventory outside the Playground are explicit native Slate fixtures, with no network backend; the Playground's creative inventory writes through the authority.

## Reproducibility and extension points

`SetupFoundation.py` authors the native input assets with the installed Unreal editor API and preserves existing ones; it creates no map. `CreateDevGridMaterial.py` and `CreatePlaygroundMap.py` author the dev grid and the Playground map, verifying rather than rewriting existing assets. The ground and movement course are built at BeginPlay, not stored in the map. `BuildFoundation.ps1` creates a fresh named Development candidate; `LaunchFoundation.ps1` opens the existing menu or, with `-DirectLevel`, the Playground. `FoundationRuntimeProbe` exists only in builds with dev automation tests (never Shipping) and is opt-in through command-line flags and feeds application events through the real controller/Enhanced Input pipeline. Its reports explicitly distinguish this from OS hardware input. `Tests/foundation-menu.mjs` tests the real CEF/native bridge and process restarts. Neither technique proves subjective mouse feel or alternate physical keyboard layouts.

Future work can replace the collision provider, eligibility facts, fixture action receiver or token presentation while retaining stable action IDs, shared settings, simulation units and diagnostics. Deferred systems and approximation boundaries are in Controls.md, Behavior.md and Verification.md.

## HUD presentation milestone 1

The `Hud` area consumes the real selected slot, existing token/offhand test double, perspective/F1/focus and existing settings. Since milestone 2 its survival/XP/attack/mode values come from the player's vitals; the milestone-1 preview data is an opt-in fixture. F3+F6 exposes its session-only controls and timed presentation sequences. The native leaf uses imported original sprites, ASCII bitmap glyphs, integer logical layout and cropped fills. It owns no gameplay rules. HUD Auto uses 320×240; the existing menu uses 416×240. Full ownership, verification and deferred systems are in [the HUD record](../Records/2026-10-07-Hud.md).

## Player vitals (HUD milestone 2)

`FFoundationVitals` owns the player's session-only health, absorption, armor stand-in, food/saturation/exhaustion, air, fall distance, experience, attack recovery, player mode and difficulty. It is a pure struct with Java 26.3 rules: the pawn feeds it one `FFoundationVitalsStep` per reference tick (displacement, grounded, sprinting, jump facts, body/eyes in water), and it feeds back death and food eligibility for the next movement step. Damage goes through one `Hurt` path (invulnerability, difficulty scaling, cooldown, armor, absorption, exhaustion, death); death respawns at the lab origin after 20 ticks. The controller restarts attack recovery on swings, misses, abandoned breaks and main-hand changes. `AFoundationLab` adds still water volumes (no collision, targeting or swimming physics) and a jump stair to a five-block drop. `UHudPresenter::ApplyVitals` maps vitals and the eye-ray target into an authoritative snapshot; the milestone-1 fixture is opt-in from F3+F6. Rules, sources, fixtures and evidence are in [the vitals record](../Records/2026-10-07-Vitals.md).

## Playground (block interaction)

The Playground (`playground`, `/Game/Maps/L_Playground`, created by `Scripts/Editor/CreatePlaygroundMap.py`) places one `AFoundationPlayground` on the same game mode, pawn, controller and HUD. It owns a session-only `FFoundationBlockWorld` (integer cells, floor division, 16³ sparse sections behind `IFoundationBlockStorage`, cell and world revisions, bounded to the whole ground) and the one `FFoundationAuthority`, which validates and commits block mutations, item counts, durability, mining progress and accepted melee exactly once. The pawn's `FFoundationInteraction` is the single owner of held-action timing and only issues commands. When the pawn has no interaction (a map without a lab), the controller falls back to the token test double `FFoundationActions`; the native ActionContracts test uses it too. `UFoundationInteractionView` presents the world and events (instanced block meshes per section and render layer, textured from the block registry and tracked by stable instance IDs, outline, preview, cracks, effects) and does not change blocks, items or vitals. It does drain the block world's change log (`TakeChanges`) on every update, even with block drawing off, so it is the log's only reader.

Per reference step: movement against the committed collision (the Playground's `GatherCollision` returns its cuboids plus blocks near the player), one vitals tick, then interaction against the resulting pose; commits reach the next movement step. Fresh presses act on an update's latest step, holds never reach back before their press, and at most one placement commits per update. The interaction and authority count steps with the pawn's `ReferenceSteps`, which, unlike the movement simulation's count, never restarts on respawn. The 26.3 blocks, their states, placement rules and items come from the block registry ([Blocks](../Blocks.md)); project blocks, tools, the loadout and the two placement presets are data (`UFoundationInteractionSettings`, Project Settings > Game > Unnamed Interaction). Rules, decisions, evidence and gaps: [the interaction record](../Records/2026-10-08-Interaction.md).

The Playground is not the only lab that can own an authority. `AFoundationLab::GetAuthority` returns it (null by default), and the generated world's `AVoxelWorld` returns its own, over streamed columns ([Voxel world](../VoxelWorld.md#streaming)). What the labs share:

- **Storage:** `IFoundationBlockStorage::IsLoaded` says whether a cell's data exists (default true, so the Playground is unchanged). `FFoundationBlockWorld::IsKnown` needs the cell inside the bounds and loaded, so targeting, placing and mining refuse cells that are not loaded. `FFoundationBlockWorld::SetStorage` swaps the storage.
- **Targeting:** the static `AFoundationLab::TraceAuthority` resolves the eye ray through an authority. The Playground's `TraceTarget` calls it, and `AVoxelWorld::TraceTarget` goes through its authority.
- **Water:** both `AFoundationLab::IsInWater` overloads are virtual. The base reads the lab's water boxes; `AVoxelWorld` reads its blocks.
- **Presentation:** `UFoundationInteractionView` accepts any `AFoundationLab` with an authority. It has two switches: `bDrawBlocks` (the instanced block meshes drawn from the change log) and `bLabFixtures` (the Playground's fixtures: the jump-stack pad and the station labels). The voxel world turns both off: its chunk meshes draw the blocks, and the fixtures belong to the Playground. The creative screen opens for any lab whose authority has `Options.bCreativeInventory`.
- **Change log:** the view drains it, so anything else that must react to an edit hooks into the storage instead. The voxel world marks sections dirty from `FVoxelBlockStorage`, not from the log.
