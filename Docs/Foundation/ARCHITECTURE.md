# Foundation architecture

Entry: existing main menu → Singleplayer → **Player Foundation** → `/Game/Maps/L_Foundation`. Existing **Super Flat** remains a separate preview. Escape opens a pause page inside the existing CEF menu; Options/Controls are the original screens and bridge. Resume and return wait for all three browser settings queues. Native `UMenuApplication` checks and drains native services before starting a selected level. Pause suspends this single-player pawn's simulation; diagnostics and UI continue ticking. It does not globally freeze Unreal's render loop.

## Ownership

- `UUnnamedInputSettings` and its `UEnhancedInputUserSettings` key profile remain the binding/hold-toggle authority and SaveGame owner. Schema 1 adds debug scale/sections. Registering existing stable row IDs retains customized mappings; new uncustomized defaults come from the native contexts. `UMenuInputSettings` validates, rejects conflicts, applies, clears intent, and saves. The project defaults are Left Shift sprint and C crouch. `CreateInputAssets.py` authors them for a new project; `SetupFoundation.py` restores only the known accidental Ctrl/Shift factory rows introduced by the first Foundation build, preserving other authored keys. Saved custom profiles are retained. No old save file is deleted or converted to HTML storage. Vanilla default keys remain research evidence, separate from the project's chosen layout.
- `UMenuPreferences` remains the single native JSON owner of sensitivity, inversion, auto-jump, sprint window, attack/use toggle, scroll sensitivity/discrete scroll, FOV and FOV effects. The pawn/router read these live. Other desired video/audio/language/pack preferences remain at their earlier implementation stage; the tooltip distinguishes the newly applied settings.
- `UMenuVideoSettings` retains fullscreen and the existing five live video settings. Its object survives pause/resume and F11 uses it. Offscreen verification deliberately has no native window-mode capability. Global engine debug exec bindings are cleared on the Foundation player controller so development F1/F5/Shift commands cannot intercept the game's controls; editor viewport shortcuts are unaffected.
- `UFoundationProfile`, configurable in `[/Script/Unnamed.FoundationProfile]` in DefaultGame.ini, centralizes reference movement constants in cm or cm/reference tick. Its C++ defaults are the verified baseline; a deliberate override belongs in that section. Block scale is a fixed project invariant: 100 cm. `FFoundationEligibility` is the future mobility/food/item-slowdown boundary; default fixture facts are mobile and sufficiently fed, with no survival system.

## Input path

Windows Slate event → physical-key adapter → capture/text/menu/global routing → Enhanced Input mapping → requested intent or typed action → fixed simulation/fixture eligibility → resolved pose/velocity/action result → telemetry.

`IMC_OnFoot` priority 0 preserves separate directional mapping rows feeding cumulative `IA_Move`. `FoundationActions` priority 10 is a transient context drawn from the registered `IMC_FoundationActions` asset, excluding debug-only mappings. The latter remain registered for settings and displayed in Controls. Only the diagnostic chord router can activate them. This prevents plain D/C/B from consuming gameplay before the modifier is held. Mouse look accumulates X/Y deltas; native axis smoothing/FOV scaling/legacy scales are disabled. The sensitivity formula is applied once, without frame-time multiplication.

`UFoundationDiagnostics` has one registered Slate preprocessor per local menu/game controller. Capture wins, followed by focused blocking UI and global diagnostics; gameplay requires possession, no menu/panel/capture, and active contexts. F3 release toggles only after an observed unconsumed F3 press. F3+F6 also works when perspective has been rebound to F6. Keyboard events that enter text continue through normal Slate/CEF character and editing dispatch. Windows layout translation is read-only; it does not switch the user's OS layout.

Opening UI, losing activation, changing bindings, or changing possession flushes intent, cancels action fixtures, and blocks held keys until release. Repeated contexts are added/removed using Enhanced Input's supported APIs, with `bIgnoreAllPressedKeysUntilRelease`. No toggle/attack resumes merely because focus returns. This cancellation policy deliberately differs from vanilla's optional toggle restoration.

Same-context or same-debug-chord duplicates are rejected; the user must clear or change the other row. Bare gameplay and debug chord keys may overlap. Overlay/modifier may intentionally share F3. Escape and the console key are reserved. Backspace unbinds during capture. Wheel is an extension: a rebound wheel pulse lasts through one reference simulation step, then releases; unbound wheel scrolls the nine slots. Positive/negative fractional accumulation and direction changes are handled independently of UI scrolling. Fixed Ctrl for stack-drop does not follow rebound sprint. Capture's selecting input is never gameplay input.

## Simulation and collision

`AFoundationPawn` is a feet-origin pawn, a world-aligned query box and one camera. Its actor and collision axes do not rotate with view yaw. `FFoundationSimulation` advances at 20 Hz; `AFoundationPawn::Tick` handles look/render interpolation independently. Maximum five catch-up steps; discarded time is explicit telemetry. Camera eye height and collision height remain separate during crouch and blocked standing. Camera-only rear/front views use a collision-clipped offset and reveal the player box.

The collision provider is `AFoundationLab`'s immutable cuboid list, with matching native engine cube components. The reference-like solver clips world-axis boxes and tests step candidates/edge support. It intentionally does not claim arbitrary Unreal mesh, moving-platform or slope support. Rebased world offsets update feet and the lab's collision/target boxes. `FoundationCoordinates` alone owns east/south/up conversion, negative flooring and inverse position/angle conversion.

## Actions and diagnostics

`FFoundationActionRequest` carries action, phase, resolved target and modifier facts. `FFoundationActionResult` carries acceptance/reason/hand. `FFoundationActions` is explicitly a test double with nine token counts and an offhand count: it cannot create items, damage entities, place terrain or mine. Eye-ray targeting uses separate 450 cm block and 300 cm entity reach, strict boundaries, and nearest-hit occlusion. The tiny numerical boundary guard is 0.0001 cm because Epic's line-box API returns a float interpolation fraction. Native collision geometry is rectangular; complex entity selection boxes are deferred.

F3 samples formatted telemetry at 10 Hz and retains at most 24 discrete events. Input contexts/priorities come from the live Enhanced Input subsystem; frame/CPU/GPU timings come from engine counters when nonzero. Unavailable counters are labelled. Target ray tests scan the small fixture list; there are no expensive terrain queries or per-frame event log writes. Debug scale, section mask and coordinate preference use the existing input SaveGame. Copy snapshot uses the native clipboard. The passive overlay is hit-test-invisible. Inventory and chat are explicit native Slate fixtures, with no inventory/network backend.

## Reproducibility and extension points

`SetupFoundation.py` authors `.uasset`/`.umap` files with the installed Unreal editor API, checks saves, and preserves existing maps. The primitive course is reproducibly constructed in `AFoundationLab::BeginPlay`. `BuildFoundation.ps1` creates a fresh named Development candidate; `LaunchFoundation.ps1` opens the existing menu or the direct lab. `FoundationRuntimeProbe` is opt-in through command-line flags and feeds application events through the real controller/Enhanced Input pipeline. Its reports explicitly distinguish this from OS hardware input. `Tests/foundation-menu.mjs` tests the real CEF/native bridge and process restarts. Neither technique proves subjective mouse feel or alternate physical keyboard layouts.

Future work can replace the collision provider, eligibility facts, fixture action receiver or token presentation while retaining stable action IDs, shared settings, simulation units and diagnostics. Deferred systems and approximation boundaries are in CONTROLS.md, BEHAVIOR.md and VERIFICATION.md.
