## Problem and change

The user's running editor and standalone preview both loaded `UnrealEditor-Unnamed-1011.dll`. The input implementation was present. Clicking Crouch and sending a Windows C key through Computer Use reproduced the dialog “That key is not supported yet.” Earlier CEF diagnostic tests injected complete physical key codes and missed this path.

Installed engine source confirms the Windows CEF adapter sends Unreal's Windows virtual key identity without the native scan code. Capture now prefers a valid DOM physical code and otherwise maps the Windows virtual key, including CEF's left/right modifier location. A regression test covers this exact missing-scan-code case. This is separate from future character movement acceptance.

The authored crouch mapping is now C; Sprint remains Left Shift. `SetCrouchDefault.py` updates only the one `key.sneak` row, preserving other mappings and modifiers. Newly created contexts also use C. Existing customized player mappings are retained; Reset Crouch adopts the new default. The first asset save was blocked by the existing preview's open package handle; the preview was closed normally through its window, leaving the editor open, and the retry saved successfully.

Key Bindings displays **Input v2** and whether edits save automatically or are session-only. The native build adds this version to its settings response. In-process editor Play remains session-only; standalone execution saves through Enhanced Input's native SaveGame slot. The seven movement keys are implemented; all other 55 rows remain Planned and disabled.

DirectX 12 was already the configured Windows default and the user's startup logs showed D3D12 active. The old mock Graphics API control still advertised OpenGL/Vulkan. It now displays **DirectX 12** and its tooltip reads the configured default and actual `GDynamicRHI` from Unreal. API switching is disabled until a validated startup/restart path exists. The duplicate DX12 config line was removed; other platform configuration remains intact.

## How to confirm the change

1. For editor Play, stop Play, close Unreal Editor, then reopen `Unnamed.uproject` so it loads `UnrealEditor-Unnamed-1012.dll`. For standalone testing, open the current candidate above. Older preserved package directories remain older builds.
2. Open Options > Controls > Key Binds. Confirm **Input v2**, **Crouch: C**, and **Sprint: Left Shift**. A preexisting custom Crouch choice is preserved; use its Reset button.
3. Click Walk Forward's W and press Up. Confirm the native row becomes Up. Done returns without reverting. Escape cancels a capture; Backspace unbinds.
4. In a save-enabled standalone run, return to the main menu, Quit Game, and reopen the same executable. Confirm Up remains, then Reset Walk Forward to W.
5. In Video Settings, hover Graphics API. Confirm **Default is DirectX 12** and **Currently running: DirectX 12**. This display is read-only.

No pawn exists yet, so these checks prove input settings and requests, not a character walking, sprinting or crouching.
