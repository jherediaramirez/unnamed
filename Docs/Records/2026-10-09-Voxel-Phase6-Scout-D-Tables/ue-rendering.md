# UE 5.8 rendering notes for block-model plants (RMC, Lumen, VSM)
Researched 2026-10-09 via WebSearch/WebFetch. "UNVERIFIED" = seen only in search snippets/forums/vendor copy.

## 1. Masked + two-sided
- Epic Blend Modes page (https://dev.epicgames.com/documentation/en-us/unreal-engine/material-blend-modes-in-unreal-engine): masked is on/off; culled pixels "aren't calculated at all". Clip value "not designed to be changed at runtime". Page says nothing about early-Z or two-sided cost.
- Early-Z: Project Settings > Rendering > Optimizations "Early Z-pass" (r.EarlyZPass) + "Mask material only in early Z-pass" (r.EarlyZPassOnlyMaterialMasking; older name r.EarlyZPassOnlyMaskedMaterials -> confirm in console). No Epic doc found. Forum (UE 4.20): enabling removed overdraw in shader-complexity view but fps unchanged (65 vs 80 fps with opacity 1). UE-117783 (VT masked needs prepass incl. masked, fixed 5.1). 5.8 forum bugs: z-fighting on masked planes (https://forums.unrealengine.com/t/masked-out-pixels-cause-camera-dependent-z-fighting-between-overlapping-planes/2747068); translucent "cast shadow as masked" vanishing with that CVar in <=5.7 (https://forums.unrealengine.com/t/r-earlyzpassonlymaterialmasking-1-bcastdynamicshadowasmasked/2742765). Features like dbuffer decals / forward shading force the prepass on.
- Two Sided Foliage shading model (https://dev.epicgames.com/documentation/en-us/unreal-engine/shading-models-in-unreal-engine): light transmission via Subsurface Color; Default Lit has no transmission so undersides go near-dark. Page doesn't describe Default Lit two-sided separately.
- Lumen perf guide (UE 5.8 docs, https://dev.epicgames.com/documentation/en-us/unreal-engine/lumen-performance-guide-for-unreal-engine): "Any pixel with materials Two Sided Foliage or Subsurface shading models are treated as foliage"; r.Lumen.Reflections.MaxRoughnessToTraceForFoliage = 0 is a cheap win.
- Normals for crossed quads (flat vs up-facing): no primary Epic source found; general industry trick, UNVERIFIED here.
- Old gamedev threads: alpha test hard edges/shimmer; alpha-to-coverage needs MSAA (not available with deferred+TSR); mips thin alpha -> use coverage-preserving mips / rescale alpha by mip (Castano: https://ludicon.com/castano/blog/articles/computing-alpha-mipmaps/, Unity mipMapsPreserveCoverage docs).

## 2. Lumen with thin/procedural geometry
- Lumen Technical Details (https://dev.epicgames.com/documentation/en-us/unreal-engine/lumen-technical-details-in-unreal-engine): Software RT represents static meshes, ISM/HISM, landscape. "Foliage and Instanced Static Mesh Components can only be supported if the mesh is using Nanite" (surface cache). Foliage needs "Affect Distance Field Lighting". "Thin surfaces may not have a good distance field representation"; walls >= 10 cm. Default 12 cards per mesh (Max Lumen Mesh Cards, offline build setting). Distance fields built from the asset's material; Two-Sided override causes mismatch. Procedural meshes not mentioned. r.Lumen.Visualize.CardPlacement 1; Surface Cache view mode shows uncovered areas pink. HWRT: "supports a larger range of geometry"; disable "Visible in Ray Tracing" to remove from HWRT scene. Page does not mention masked/alpha in HWRT.
- Lumen perf guide: HWRT target < 100k instances in RT scene; TLAS rebuilt each frame; "Large meshes that overlap the entire scene are a performance issue"; stat SceneRendering ("Ray tracing active instances"), stat GPU, ProfileGPU, r.Lumen.AsyncCompute 0.
- HWRT alpha masking: r.Lumen.HardwareRayTracing.SurfaceCacheAlphaMasking exists; bug UE-347428 (landscape masked, 5.5, target 5.8) https://issues.unrealengine.com/issue/UE-347428. No cost numbers anywhere. UNVERIFIED on foliage specifics.
- Runtime meshes: ProceduralMeshComponent gets no offline distance field (old forum https://forums.unrealengine.com/t/uproceduralmeshcomponent-with-distance-fields/354509); only screen traces + whatever HWRT sees. Forum (5.8) "Mesh terrain doesn't work with software lumen... works ok with hardware lumen" https://forums.unrealengine.com/t/mesh-terrain-doesnt-work-with-software-lumen/2730678.
- RMC: free Core (MIT, github.com/TriAxis-Games/RealtimeMeshComponent) has NO Lumen/SDF per vendor page https://triaxis.games/realtime-mesh/ . Pro ($49, Fab) lists "Lumen support (Card generation)" and "Distance Field support" (runtime, GPU or CPU path; 5.5-5.8). GitHub issues search "lumen": only #303 (2026-09-03, "Meshes are not rendered in the base pass on UE 5.8") and #288. Check #303 before upgrading to 5.8.
- Third party: AZLumenRuntime (May 2025, UE 5.3.2/5.5.4, needs HWRT GPU unless engine modified) https://forums.unrealengine.com/t/2522973 ; vendor claims, UNVERIFIED.
- Cards for many small cutout instances: no source found. Cross-quad plants are tiny open surfaces; expect no/low-quality cards and SDF. Practical: exclude from Lumen scene (see 5).
- "Lumen Lite" in UE 5.8 mentioned in a headline (guru3d; page 403) - UNVERIFIED, check release notes.

## 3. Shadows (VSM)
Epic VSM page (https://dev.epicgames.com/documentation/en-us/unreal-engine/virtual-shadow-maps-in-unreal-engine):
- "Non-Nanite geometry is much more expensive to render into VSMs than Nanite geometry"; individual draw calls; needs LODs or "extremely expensive to render into small pages"; disabling non-Nanite in coarse pages can be a big win; r.Shadow.Virtual.MarkPixelPagesMipModeLocal.
- Cache invalidated by moving/adding/removing casters (pages overlapping bounds), WPO/PDO/skeletal every frame. Add/remove of a chunk section => invalidates overlapping pages (relevant to RMC section rebuilds). Per-primitive Shadow Cache Invalidation Behavior (Auto/Always/Rigid/Static).
- Foliage: "using only Contact Shadows is a sufficient substitute" for grass; disable dynamic shadow casting on distant objects; r.Shadow.RadiusThreshold culls small non-Nanite objects on CPU; r.Shadow.Virtual.UseFarShadowCulling; beyond Dynamic Shadow Distance Movable Light non-Nanite goes to Distance Field Shadows (needs DF!).
- Page doesn't cover masked cost or Shadow Pass Switch. Epic issue: two-sided foliage w/ opacity 0 ignores VSM shadows (closed by design) - UNVERIFIED detail. Forum 5.6.1 dense foliage: Shadow Depths ~7.5 ms.
- Tom Looman guide https://tomlooman.com/unreal-engine-optimization-farfarwest/ (masked foliage effort).

## 4. Voxel renderer lessons
- Sodium: all blocks one shader; "Material Downgrading" (0.6) moves geometry to simpler pass when texture has no transparency; 0.7 translucency quad splitting + sorting. Vanilla leaves/plants cutout vs translucent. Add-ons: Complex Leaf Culling (hide shared leaf faces, edge leaves translucent->cutout), Cullify (hide grass/flowers by distance, hooks Sodium LevelSlice). Source for details: github.com/CaffeineMC/sodium (read only for ideas).
- Godot Voxel Tools blocky docs https://voxel-tools.readthedocs.io/en/latest/blocky_terrain/ : alpha clip goes through opaque pass; 3 materials on one atlas (opaque, clip, transparent); transparency_index culling; culls_neighbors off for dense foliage; only faces on cube sides can be culled ("dramatic slowdowns" otherwise); keep custom models low-poly; reuse materials; AO via vertex colors baked on cube edges; no random-offset support documented.
- Not found: any UE voxel/Minecraft-clone write-up about cross-quad plants + Lumen. Voxel Plugin 2 claims runtime Nanite+Lumen (80.lv announcement), unverified.
- Alpha mips thinning: use coverage-preserving mips or rescale alpha; tune cutoff per texture; grass vs leaves differ.
