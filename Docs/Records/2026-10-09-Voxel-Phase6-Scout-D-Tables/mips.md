# Alpha-tested foliage mips: research notes (2026-10-09)

Verification key: [V] fetched/seen in a source this session; [M] from memory / unverified.

## 1. Why coverage is lost
Castano, "Computing Alpha Mipmaps" (Sept 2010, The Witness blog; https://www.ludicon.com/castano/blog/?p=1218 ): "each mipmap has a different alpha test coverage ... the proportion of pixels that pass the alpha test changes, in most cases going down." Box filtering averages opaque (1) and transparent (0) texels, so thin features fall below the cutoff (0.5) and vanish; RGB of transparent texels also bleeds in (dark fringes) [V for coverage quote]. Hard alpha test additionally gives binary, aliased edges that shimmer as sub-pixel features cross the cutoff (Golus 2017, Wyman 2017) [V/M].

## 2. Fixes
(a) Coverage-preserving mips (Castano 2010; NVTT alphaTestCoverage()/scaleAlphaToCoverage(); DirectXTex ScaleMipMapsAlphaForCoverage https://source-hub.etos-pro.ru/microsoft/DirectXTex/wiki/ScaleMipMapsAlphaForCoverage ). Measure fraction of mip0 texels with alpha > cutoff (A_r). For each mip: bisect a threshold a_r in [0,1] giving same fraction in that mip, then scale alpha by A_r/a_r (clamp). Offline, cost = few counting passes per mip; zero runtime cost. [V] Needs the cutoff known at bake time (for alpha-to-coverage Castano suggests ~1.0 threshold... "near 1").
(b) Alpha-to-coverage: Golus, "Anti-aliased Alpha Test: The Esoteric Alpha To Coverage" (Aug 2017) https://bgolus.medium.com/anti-aliased-alpha-test-the-esoteric-alpha-to-coverage-8b177335ae4f (403 on fetch; details via search summaries). Targets forward renderer with >=4x MSAA; alpha becomes the MSAA coverage mask. Without MSAA there is no sub-pixel mask, so it degenerates to plain alpha test (Unity docs: "meant for MSAA; without MSAA, results unpredictable"). [partly V]
(c) Golus: shader sharpening: a = (alpha - cutoff) / max(fwidth(alpha), eps) + 0.5, i.e. keeps the edge ~1 px wide; plus a mip-level alpha scale (default ~0.25 in his shader, applied only when mips don't preserve coverage). Cost: one fwidth + math per pixel. Works without MSAA but then output is aliased/binary (use with AA, or feed A2C). [V via Dolphin issue 11626 reproduction; formula is M]
(d) Hashed alpha testing: Wyman & McGuire, "Hashed Alpha Testing", I3D 2017 (https://research.nvidia.com/sites/default/files/pubs/2017-02_Hashed-Alpha-Testing/Wyman2017Hashed.pdf; PDF unreadable via fetch). Stochastic threshold from hash of object-space position, scaled by derivative so noise is ~pixel sized and stable under camera/object motion; expected coverage equals alpha, so no coverage loss, converges under temporal accumulation. Cheap per-pixel hash; wants TAA/TSR to resolve noise; noisy without it. Pairs naturally with TAA. [M, abstract-level]
(e) Others: dilate/bleed RGB of opaque texels into transparent texels (and premultiplied-alpha filtering) so mips have no dark/white fringes; max-alpha mips (over-thickens: Minecraft MC-302915 "mipmapping on cutout textures can cause them to appear larger"); build each mip from mip0 (not previous mip) with snapped alpha (Minecraft "cutout"); discard-zero-alpha texels from average (Minecraft "dark_cutout"). [V for Minecraft ones]

## 3. Vanilla Minecraft Java
- Historic layers: SOLID, CUTOUT, CUTOUT_MIPPED, TRANSLUCENT (Yarn 1.21.7 BlockRenderLayer enum lists all; Forge 1.11.2/1.12.2 javadocs same). NeoForge docs: cutout_mipped "will scale down textures at large distances to avoid visual artifacts", used e.g. by leaves; plain cutout (unmipped) for glass-like blocks; cutout_mipped_all applies mips to items too. https://docs.minecraftforge.net/en/latest/rendering/modelextensions/rendertypes/ . Exact grass/flower assignment: unverified (didn't read decompiled source per rules). MC-226260 (grass/snow edge mip artifacts) and 1.9 "leaves look opaque at distance with mipmaps = works as intended" noted.
- 25w43a (released 2025-10-21): `darkened_cutout_mipmap` replaced by `mipmap_strategy` (wiki https://minecraft.wiki/w/Java_Edition_25w43a). Quote: "`cutout` is a new strategy that always generates a mipmap based on the original texture"; auto = default, picks `mean` for textures without fully transparent pixels, `cutout` for those with. `dark_cutout` is the successor of the darkened behaviour (used for leaves, mangrove roots). Fixes MC-302915.
- Allowed values (wiki Resource pack page, https://minecraft.wiki/w/Resource_pack): auto (default), mean, cutout, strict_cutout, dark_cutout [V]. Semantics from NeoForged 1.21.11 docs https://docs.neoforged.net/docs/1.21.11/resources/client/textures : mean = average 4 pixels; cutout = mean but all levels generated from original, alpha snapped to 0/1 at threshold 0.2; strict_cutout = cutout with threshold 0.6; dark_cutout = mean but neighbours only included if alpha != 0. (NeoForge doc says mean default; wiki and 25w43a say auto - wiki/patch notes win.)
- `alpha_cutoff_bias` (float, default 0): per search of Mojang 1.21.11 Pre-Release 1 notes (https://www.minecraft.net/fr-fr/article/minecraft-1-21-11-pre-release-1), added there with resource pack format 75.0; "Only used for lower mips of cutout textures, does not change the alpha of first mip level, and has no effect on other textures." Adds to the snap threshold (cutout 0.2 + 0.3 = 0.5). Added in 1.21.11 pre-release 1 per search summary [not fetched directly; moderately verified]. Community MCME 26.2 changelog repeats it but is a carry-over.
- Render layers: 26.1 Snapshot 7 (https://minecraft.wiki/w/Java_Edition_26.1_Snapshot_7): render pass now determined by sprite contents: any translucent pixels -> translucent pass; any fully transparent pixels -> cutout pass; else solid. New texture-entry field `force_translucent`. So per-block cutout vs cutout_mipped distinction is superseded by per-texture mipmap_strategy (the wiki text doesn't say "cutout_mipped removed" explicitly; unverified whether the enum constant itself was deleted). 26.2: MC-308245 fix for flower ghosting when mipmapped (wiki Java Edition 26.2, seen in search only).
- Mipmap Levels option: wiki Options page shows values 2 and 4 plus off; range 0-4 [partially V]; the wiki does not list a change in 25w43a. Exact slider range in 26.x: unverified.

## 4. Unreal Engine mapping
- Masked material + Opacity Mask Clip Value: plain alpha test (hard, aliased). Clip value is a cutoff trade-off, not an anti-shimmer fix.
- Texture "Scale Mips for Alpha Coverage" (bDoScaleMipsForAlphaCoverage, FVector4 AlphaCoverageThresholds per channel; 0 disables channel; typical 0.5-0.9): exists in Texture (Python API do_scale_mips_for_alpha_coverage, UE 5.0/5.4 docs https://docs.unrealengine.com/5.4/en-US/PythonAPI/class/Texture.html [V via search summary]); implemented in the texture build/compressor for imported 2D textures. UE-102673 reports a bug (AlphaScale computed from source rather than dest) https://issues.unrealengine.com/issue/UE-102673 . Texture2DArray support: unverified. Since we generate mips in C++ ourselves (mip data supplied), engine option is irrelevant; implement Castano's algorithm directly.
- Mip Gen Settings (Sharpen0-12, Blur, FromTextureGroup, LeaveExistingMips, NoMipmaps) [M]: sharpen filters RGB+A, not coverage-aware.
- DitherTemporalAA node / Dither Opacity Mask: requires TAA/TSR (Epic docs); dont combine with MSAA (Cesium blog 2022-10 https://cesium.com/blog/2022/10/20/smoother-lod-transitions-in-cesium-for-unreal/ ). Equivalent to hashed/dithered alpha.
- Alpha-to-coverage: only forward renderer + MSAA; Epic staff said not supported in 4.15 forward; in forward+MSAA, masked opacity becomes coverage [V forum, old]. Not available in deferred+Lumen+TSR. Unverified for 5.8.
- TSR: official docs claim reduced flicker on complex geometry; nothing specific on masked leaves. Forum claim of "Thin TSR" in 5.7/5.8 unverified. https://dev.epicgames.com/documentation/en-us/unreal-engine/temporal-super-resolution-in-unreal-engine . Texture UI doc page fetch returned empty; no Epic foliage-at-distance guidance found for Electric Dreams/Valley.

## 5. Recommendation (16x16 nearest-filtered arrays, deferred + TSR)
Own mip gen: (1) mip0 alpha 0/1 (pixel art); build each mip from mip0 with a box/area average over the covered footprint, RGB premultiplied-weighted (only opaque texels contribute; avoids dark fringes); (2) coverage-preserving alpha scale per mip (Castano bisection) against the shader cutoff (0.5); store alpha as soft values in mips; (3) shader: Golus fwidth sharpening around cutoff for a ~1px edge, optionally combined with a small per-mip cutoff bias; (4) optionally add dithered/hashed threshold (DitherTemporalAA-style) to let TSR integrate residual edge, test vs. none; (5) nearest magnification at mip0 but trilinear/linear between mips at distance (anisotropic helps thin quads). Minecraft's own answer is "cutout/strict_cutout" mips from original with snapped alpha and alpha_cutoff_bias tuning; flowers use strict_cutout, leaves dark_cutout. I did not find a primary source for Vintage Story/Teardown/Sodium specifics (unverified).
Test: fixed camera, grass/flower patch at N distances (e.g. 4,8,16,32,64,128 blocks), TSR on and off, 100% screen pct; capture frames, compute mean opaque pixel fraction (alpha-tested coverage mask via a debug unlit material or custom stencil) per distance and compare to analytic coverage of mip0 * projected area; target within ~5%. Also capture 30 frames with 0.1-px camera jitter motion and compute per-pixel temporal variance on foliage to quantify shimmer; compare variants A (box), B (coverage-scaled), C (+fwidth), D (+dither).
