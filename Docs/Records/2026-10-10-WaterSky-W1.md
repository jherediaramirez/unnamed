## What changed

**The block table** (`Blocks/VoxelBlockTable.h`, `Voxel/VoxelBlocks.cpp`):
- `EVoxelFluid` (none, water, lava), and `Fluid` and `FluidLevel` in `FVoxelStateInfo`. The two fields sit in existing padding, so the struct stays 68 bytes (the static assert in `VoxelOreLooks.cpp`).
- `IsFluidSource()`. `MakeTable` fills both fields from the registry's `GetFluid` for every state.

**Three readers** took `FluidAmount == 8` as "a source". Falling fluid has amount 8 too, so all three now use `IsFluidSource()`:
- the freeze pass (`Surface/VoxelFreezePass.cpp`, both passes);
- `FVoxelBlockPredicates::GetFluidBits`;
- `FVoxelPlantSurvival::IsWaterSource`. This third reader was found in W1; the manager approved the fix, and it is noted for S7b, which works on plant survival.

Generation writes only sources, so no generated cell changes: the goldens and hashes are identical (Gate, below).

**`Source/UnnamedVoxel/Fluids/`** (UObject-free, deterministic, no randomness):
- **`VoxelFluidRules.h`**, header-only templates over a reader or world:
  - `FVoxelFluidCell` is the rules' view of a cell: its fluid, its level, the collision faces it covers (walls), solid, waterloggable, washed away, unknown, and the few named blocks (soul soil, blue ice, obsidian, cobblestone, stone, basalt).
  - `GetParams`:
    - water acts every 5 ticks, drops 1 per cell and finds drops up to 5 cells away;
    - overworld lava acts every 30 ticks, drops 2 per cell and finds drops up to 3 away;
    - both follow the game rules `water_source_conversion` and `lava_source_conversion`.
  - `Derive`: a flowing cell's state from its neighbours.
  - `FindSpreadSides` and `FindDrop`: the drop search, a breadth-first walk through passable cells that never goes back through the spreading cell.
  - `Act`: one scheduled act. It is pure, and its writes carry a compare-and-set `Before`. It returns false when it reads an unknown cell, so the act can wait for streaming (W2a).
  - `React`: lava meeting water above or beside it, never below.
  - `Apply`: every change goes through it. It sets the cell, lets placed lava react at once, and wakes the neighbours in the order west, east, down, up, north, south.
  - `RunTick`: one game tick.
- **`VoxelFluidScheduler`**: a min-heap on (due tick, order scheduled), so acts due in the same tick run first in, first out. It keeps one pending act per cell and fluid, and a second request is dropped.
- **`VoxelFluidTestWorld`**: superflat stone up to y 63, a map of the cells that were set, a `uint64` tick, and `Place` (an edit, as `/setblock`) and `Step`.
- **`EVoxelFluidMutation`**: test-only breakages, in the same pattern as `EVoxelDecorationMutation`.

## Results

- `w_plane`, `w_slab` and `l_plane0`: 67 of 67 checkpoints equal the probe.
- `l_drain0`: 64 of 64.
- `w_drain`: 64 of 67. The first difference is at t=80, in one cell.

**The drain's transients:**
- In `w_drain`, five cells in one quadrant empty 5 ticks before the probe: (0, -2) and (1, -1) at 85 instead of 90, and (0, -3), (1, -2) and (2, -1) at 90 instead of 95. The plane is dry at t=95 in both.
- These are same-tick order effects (Q9 (a)): reported, not pinned. The probe's drain is a perfectly symmetric checkerboard.
- A Python model of these rules (`C:\dev\sandbox\water-w1\ordersearch.py`) replays it exactly under either of two assumptions:
  - an act can't reschedule itself. This contradicts `w_falling_lands`, where the source must act again at t=10;
  - or the first two neighbours woken are perpendicular (16 of the 24 horizontal orders), which the wiki's west, east, …, north, south is not.
- Neither is explained by a source, so the core keeps the wiki's order. An open question for a later probe.

## Known gaps (none is pinned by a probe)

- **Waterlogged non-model blocks read as dry:** the block import fills a state's water for model blocks only (`Scripts/Editor/BlockImportData.py` 210-224), so a waterlogged slab's `Fluid` is none in the game table. The rules handle waterlogged slabs: the test world gives them water directly. W2b (waterlogging).
- **Cases no probe covers**, where the rules follow the nearest probed rule:
  - flowing water over a still source below is treated as over a drop, so it doesn't spread sideways (probed only over falling water, `w_cliff`);
  - a dry slab between two sources stays dry;
  - a cell with sources around it over a drop;
  - two slab halves side by side: walls are whole faces only;
  - water going down into lava is blocked. It is unreachable here, because lava converts first when water arrives above or beside it.
- **Same-tick order:** see the drain above.
- **Nether lava** (`fast_lava`: every 10 ticks, reach 7) is not modelled. No dimension uses it yet.
